# Fleet: milestone-scoped team dispatch with per-epic lanes

**Supersedes:** ADR-0003 (fire-and-forget run), ADR-0005 (worktree-per-bean), ADR-0008 (no lifecycle state) — at the architectural level.
**Amended:** 2026-07-08 — per-epic worktree model (originally serialized single-worktree; see ADR-0014 for the per-epic refinement).

Hordr grows a **fleet** model on top of the existing `hordr run` primitive. A fleet is the runtime instance of one team (an Agent Companies package, ADR-0007) working one **milestone bean** in one **worktree**. It is bounded 1:1:1 — one milestone → at most one active fleet → exactly one worktree (branch `milestone/<id>`). `hordr fleet finish` tears all three down together.

A fleet runs a **dispatch loop** owned by the daemon, but the model is now **per-epic** (ADR-0014): each unblocked epic under the milestone gets its own **lane** — a worktree branched from the milestone integration branch, a pane, and a serialized dispatch loop. Lanes are parallel across epics; within each lane, tasks are serialized (one at a time, driven by `--blocked-by` chains). Worktrees are created lazily: only when the epic becomes unblocked, so later epics auto-inherit earlier epics' merged code from the integration branch. There is no Director agent — planning is external, and the daemon is the supervisor. Each task is worked by a fresh, hordr-run-equivalent invocation that terminates on completion. Roles are derived from each bean's `assigned:` field and resolved against the company manifest at spawn time.

Rationale: the prior "fire-and-forget, one bean = one worktree = one shot" model (ADR-0003/0005) could not express a team working a shared body of work over time. Rooting the fleet in a milestone bean (not a free-floating namespace like cafleet's `fleet_id`) and routing work through bean state (not a message bus) keeps beans as the single source of truth while adding coordination. Per-epic lanes give parallelism (the team's value) without the concurrent-committer problem — each lane has its own worktree, serialized within, so git stays clean and "one task = one commit" is trivially true within a lane. Cross-epic dependencies resolve themselves through lazy worktree creation: a worktree branches from the milestone integration branch at creation time, by which point blocking epics have already merged (ADR-0014).

The trade-off is explicit: hordr is no longer stateless (ADR-0008 is reversed — see ADR-0012) and no longer purely fire-and-forget inside a fleet. The daemon owns a per-fleet loop and SQLite-backed process state. Outside a fleet, `hordr run`/`hordr cleanup` behave exactly as before.
